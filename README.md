# Log Sanitizer

*English: an offline, single-file HTML tool that strips secrets and PII (keys, tokens, e-mails, IPs, cards, ...) from logs, tickets and configs before you share them. No network, no dependencies, no build step. MIT.*

Люди копируют логи вместе с паролями, токенами и адресами, а потом отправляют их коллегам, в тикет, в чат или ИИ-ассистенту. Log Sanitizer убирает такие данные локально в браузере: достаточно скачать один файл `log-sanitizer.html` и открыть его двойным кликом.

## Возможности

- Один самодостаточный файл (HTML, CSS и JS внутри), без сборки и зависимостей.
- Ничего не уходит в сеть. Строгий Content-Security-Policy (`default-src 'none'`) технически запрещает запросы. Можно отключить интернет и убедиться.
- Каждый тип данных включается отдельным чекбоксом, есть белый список и свои слова или регулярки.
- Четыре режима замены, стабильные псевдонимы и обратное восстановление по карте соответствий.
- Одноходовая замена с разрешением пересечений, работает на входе до 5 МБ.
- Повторный прогон уже очищенного текста безопасен: собственные метки не маскируются.

## Что находит

| Тип | Что ловит | По умолчанию |
|---|---|---|
| E-mail | адреса вида `name@domain.tld` | вкл |
| IPv4 | четыре октета 0-255; версии в контексте `version`/`v` не считаются | вкл |
| IPv6 | полные и сжатые формы (строгая проверка, время `10:23:45` не ловится) | вкл |
| MAC | `aa:bb:cc:dd:ee:ff`, `aa-bb-cc-dd-ee-ff` | вкл |
| JWT | три base64url-части, начало `eyJ` | вкл |
| Ключи по префиксам | AWS (`AKIA`/`ASIA`), GitHub (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`), Slack (`xox[baprs]-`), Google (`AIza`), Stripe (`sk_live_`, `rk_live_`), npm (`npm_`), GitLab (`glpat-`) | вкл |
| Заголовки авторизации | `Authorization: Bearer/Basic ...`, `X-Api-Key`, значения `Cookie`/`Set-Cookie` (атрибуты `Path`, `Expires` и т.п. не трогаются) | вкл |
| Ключ=значение и JSON | значения полей `password`, `passwd`, `pwd`, `secret`, `token`, `api_key`, `apikey`, `access_key`, `private_key`, `client_secret`, `auth`; имя поля остаётся | вкл |
| Учётные данные в URL | `scheme://user:pass@host`: маскируются user и pass | вкл |
| Приватные ключи | блок `-----BEGIN ... PRIVATE KEY-----` ... `-----END ... PRIVATE KEY-----` целиком | вкл |
| Банковские карты | 13-19 цифр (с пробелами и дефисами), первая цифра 2-6, только если проходит проверку Луна | вкл |
| IBAN | только если проходит проверку mod 97 | вкл |
| Телефоны | международный формат: `+` и 8-15 цифр, консервативно | вкл |
| Внутренние хосты и FQDN | имена с известными TLD и внутренними зонами (`.internal`, `.corp`, `.local` и т.п.) | выкл |
| UUID | стандартный вид 8-4-4-4-12 | выкл |
| Имена пользователей | `user=`, `username:`, `for <name> from` | выкл |
| Свои слова и регулярки | по одному на строку, префикс `re:` для регулярки | выкл |

Опция «не трогать приватные и loopback адреса» (по умолчанию выключена) пропускает `10/8`, `172.16/12`, `192.168/16`, `127/8`, `169.254/16`, а для IPv6 `::1`, `fe80::/10`, `fc00::/7`.
Белый список: значения, которые никогда не маскируются (по одному на строку, точное совпадение).

## Режимы замены

1. **Тип**: `[EMAIL]`, `[IPV4]`, `[JWT]`, `[SECRET]` и т.д.
2. **Псевдонимы**: `EMAIL_1`, `IPV4_1`, `IPV4_2`. Одно и то же значение всегда получает один и тот же псевдоним в рамках сессии.
3. **Частичная маска**: остаются последние 4 символа (`************1234`), только для карт, ключей и токенов; остальные типы ведут себя как «Тип».
4. **Удаление**: `[REDACTED]`.

## Как пользоваться восстановлением

1. Выберите режим «Псевдонимы» и очистите текст. Отправьте очищенный текст ассистенту или коллегам.
2. Нажмите «Скачать карту соответствий (JSON)». **Файл содержит оригинальные секреты: не передавайте его дальше.**
3. Когда придёт ответ с псевдонимами, откройте вкладку «Восстановить», вставьте ответ, вставьте или загрузите карту (если поле карты пустое, берётся карта текущей сессии) и нажмите «Восстановить».

Подстановка идёт от самых длинных псевдонимов к коротким, поэтому `IPV4_10` не ломается заменой `IPV4_1`. Карта живёт только в памяти страницы: ничего не пишется на диск и в localStorage, пока вы сами не скачаете файл. Кнопка «Очистить текст» также стирает карту сессии.

## Как это работает

- **Одноходовое обнаружение.** Все включённые детекторы сканируют исходный текст и собирают совпадения (позиции, тип, приоритет). Затем пересечения разрешаются по приоритету: приватные ключи > JWT и ключи по префиксам > учётные данные в URL > заголовки и пары ключ=значение > карты и IBAN > e-mail > IP и MAC > телефоны > остальное. При равном приоритете побеждает более длинное совпадение. После этого текст собирается за один проход по позициям, без последовательных `replace` по всему тексту. Поэтому, например, пароль внутри URL или токен внутри JSON-поля маскируются один раз и корректно.
- **Почему псевдонимы стабильны.** Сессия хранит таблицу «тип + исходное значение → псевдоним» и счётчики по типам. Повторное значение берёт готовый псевдоним, новое получает следующий номер. Если в тексте уже есть строка вида `EMAIL_1`, такой псевдоним не выдаётся, чтобы восстановление не путалось.
- **Идемпотентность.** Значения, которые сами являются метками (`[EMAIL]`, `EMAIL_1`, `****1234`), не маскируются повторно.
- **Вывод.** Результат показывается в textarea, а подсветка (по желанию) строится через DOM API и `textContent`, без `innerHTML` с пользовательскими данными. Для очень больших результатов подсветка отключается.
- **Код.** Чистая логика (без DOM) заключена между маркерами `LOGIC:START` и `LOGIC:END` в `log-sanitizer.html`, тесты достают её оттуда напрямую.

## Модель угроз и ограничения

Цель: не передать секреты случайно при копировании логов. Инструмент работает в браузере пользователя и не имеет сетевого доступа.

Чего инструмент **не гарантирует**:

- Он находит только **известные шаблоны**. Это не замена ручному просмотру: всегда перечитывайте результат перед отправкой.
- Имена людей, названия компаний, номера заказов и произвольные бизнес-данные без характерного шаблона **не находятся** (для них есть свои слова и регулярки).
- Секреты в нестандартном формате, разбитые на несколько строк или закодированные (base64, URL-кодирование, экранирование в JSON), могут быть пропущены.
- Карта соответствий **содержит оригиналы** секретов. Храните её как секрет и не передавайте тем, кому не доверяете оригинал.
- Пользовательские регулярки выполняются как есть: слишком сложная регулярка может подвесить вкладку.
- Телефоны и карты ловятся консервативно (только `+` и международный формат; карты с проверкой Луна и первой цифрой 2-6), поэтому возможны пропуски и редкие ложные срабатывания.

Сообщить о проблеме: см. [SECURITY.md](SECURITY.md).
